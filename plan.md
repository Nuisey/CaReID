# Plan: CarID Dashboard Web Application

This document outlines the architecture, features, and implementation steps for building the Flask-based web application to track neighborhood vehicles, integrating with your existing `CaReIDInference` pipeline.

## 1. System Architecture [IMPLEMENTED]

Instead of reinventing the wheel, the Flask backend will act as a real-time monitor on top of your existing Re-ID pipeline.

*   **Backend (Python Flask)**: 
    *   Serves the UI (HTML, CSS, JS).
    *   Monitors `CaReIDInference\Data\CarLabels_Unprocessed.csv` for new vehicle detections.
    *   Serves vehicle images directly from `CaReIDInference\Data\Unconfirmed`.
    *   Maintains a persistent state (in `state.json`) for the customized house boxes and vehicle home/away statuses.
*   **Frontend (Vanilla JS/HTML/CSS)**: 
    *   **Homepage**: An interactive map using `houses.png` as the background. Allows creating and dragging "house" containers, managing car icons, assigning IDs, and visualizing real-time Home/Away states.
    *   **Timeline**: A real-time updating vertical feed showing recent vehicle detections, their images, identities, and whether they are arriving or leaving.

## 2. Core Features & Implementation Details [IMPLEMENTED]

### A. Homepage (Interactive Map)
*   **Background**: `houses.png` will be copied to the Flask `static` folder to be served as the background of a designated map container.
*   **Customize Button**: Prompts the user (e.g., via a modal or native prompt) for a number of cars. It generates a draggable `<div>` containing that many car icons (using SVGs).
*   **Drag & Drop**: Implemented using HTML5 Drag and Drop or mouse-tracking events. The absolute/relative coordinates of each box relative to the background will be saved to `state.json` via a backend API.
*   **Car Assignment**: Clicking on a gray car icon will open a dropdown/modal populated with entries from `label_map.csv`. Selecting one binds that Re-ID to the icon.
*   **State Toggling**: Polling the backend every few seconds. If a car is "Home", the icon turns blue. If "Away", it turns gray.

### B. Timeline (Activity Feed)
*   **Feed Construction**: The backend will read `CarLabels_Unprocessed.csv` and parse the timestamp from the `filename` (e.g., `2025-11-08_12-41-24-474993__car_97858.jpg`).
*   **Display**: A scrollable vertical list. Each card will show:
    *   Image of the car (served by Flask from the `Unconfirmed` folder).
    *   Timestamp of detection.
    *   Vehicle Identity (Make, Model, Color, ID).
    *   Event Type: "Arriving" (Blue indicator) or "Leaving" (Gray indicator).

## 6. Handling Conflicting Burst Labels (Track-Level Identity) [IMPLEMENTED]

**The Problem:** When a car drives by, YOLO captures a burst of images (e.g., 5 frames). Because of blur, lighting, or angle changes, the ReID model might classify 4 frames as "Car A" and 1 frame as "Car B". Or worse, it might output 4 different labels for the 4 frames. Currently, the system treats each image independently.

**Proposed Strategies to Stabilize Identities:**

1.  **Enforce YOLO Tracking IDs (The Root Fix):**
    *   Currently, YOLO tracks the car frame-to-frame using an internal ID (e.g., `track_id=15`), but the ReID script doesn't utilize this to group the images.
    *   We can inject the YOLO `track_id` into the filename (e.g., `timestamp__arriving__track15__car.jpg`). 
    *   The backend will then *know* with 100% certainty that these 5 images are the exact same physical vehicle, regardless of what the ReID model guesses.
2.  **Majority Voting Consensus:**
    *   Once grouped by `track_id` or a tight 2-second time window, we tally the predictions. If 4 images say "Car A" and 1 says "Car B", we enforce "Car A" for the entire burst. 
    *   If there is a tie, we break it by picking the label that has the highest combined confidence score.
3.  **Absolute Max-Confidence Override:**
    *   Ignore voting completely. Out of the 5 images, find the single image with the absolute highest ReID confidence score (e.g., 98%). The system assumes that frame had the clearest view, and forcefully assigns its label to all other images in that burst.
4.  **Feature Averaging (Advanced):**
    *   Instead of looking at the text labels, we modify your ReID script to take the raw mathematical vectors (embeddings) of all 5 images and average them together into one "Super Vector". We then compare this average vector against your Gallery. This mathematically neutralizes motion blur and glare from individual bad frames.

**Recommendation:** Strategy #1 combined with #3 is the easiest and most effective to implement right now. By passing the YOLO `track_id` to the backend, we can group the burst perfectly and just display the single highest-confidence label for that specific tracked object.

## 7. High-Speed 'Label' Page (Bulk Confirmation)

**The Goal:** A lightning-fast interface to review the `Data/unsynced` folders (which contain images pre-filtered by high YOLO confidence or Gemini agreement) and officially commit them to the true `Gallery`. Because of the strict filters, ~80-90% of these will be correct, so the UI must be optimized for bulk approval rather than individual clicking.

1. **The Skim Interface (UI):**
   * The page will display masonry grids grouped by the predicted Label (e.g., all "White,Honda,CR-V" images together).
   * **Default State:** All images are pre-selected.
   * **Action:** You skim the grid. If you spot an incorrect image, you click it to deselect/reject it. 
   * **Execution:** You click a massive "Confirm 50 Images" button at the top of the group.

2. **Backend Commit Logic:**
   * When confirmed, the backend physically moves the image files from `Data/unsynced/<label>/` into the flat `Data/Gallery/LabeledCarDataPhotos/` folder.
   * It looks up the correct ID for the label in `Data/label_map.csv`.
   * It appends a new row to `Data/Gallery/Gallery.csv` (format: `filename.jpg,ID`), permanently making it ground-truth data for future ReID training and reference.

3. **Accuracy Metrics & Logging:**
   * The backend will maintain a `Data/sync_metrics.json` file.
   * Every time a batch is processed, it logs: Total images presented vs. Total images rejected/corrected.
   * The top of the Label page will display live statistics: "Total Images Processed: 5,420 | AI Accuracy Rate: 88.5%".
